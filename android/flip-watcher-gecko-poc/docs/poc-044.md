# Gecko POC 0.4.4 — identify the last unmet condition

Physical 0.4.3: TIMEOUT / DEADLINE, requests 2/8, confirmed ID count 0.
This proves two navigation requests passed the native gate. It does not prove
which phase timed out, that a native reload completed, or that the final address
was an exact permalink. Do not infer any of those from the count alone.

## Changes

The app now keeps only a fixed enum for the last unmet requirement in RAM.
At the original 20-second deadline its code becomes the persisted timeout reason:

| Code suffix (DEADLINE_) | Last unmet condition |
| --- | --- |
| LOCATION | Current location bound to an accepted request |
| SOURCE_LOADING | First document completion before one native re-opening |
| PORT | Connected private content port |
| NEW_PORT | New generation after the navigation began |
| PORT_ADDRESS | Port sender URL equals native URL |
| CONTEXT_REPLY | A response to the private context request |
| CONTEXT_PROTOCOL | Correct reply schema/nonce/types |
| DOCUMENT_FRESHNESS | Document created after navigation boundary |
| DOCUMENT_COMPLETE | Safe fresh document reaches complete |
| NATIVE_PROGRESS | Exact URL and complete document available; progress still below 100 |
| EXACT_PERMALINK | Complete safe fresh document still at an opaque share address |

These are observations, not inferred root causes. Freshness failure alone cannot
distinguish stale document, missing metadata or clock precision. Port-address
mismatch does not identify the destination. No URL, post ID, epoch, text, cookies,
token, consent or nonce is stored. Exactly the same four-field private record:
status, fixed reason, request count, confirmed-ID count. Timeout reasons cannot
claim STOP or CONFIRMED, and old DEADLINE records remain readable. Old 0.4.3
records cannot be retroactively assigned a more specific phase.

The private reply parser now distinguishes absent/malformed/stale/unsafe/loading/
complete. Unsafe wins over stale/incomplete and still stops immediately. Public
page messages cannot authorize this native flow. The compatibility method retains
its fail-closed Pair/null behavior for existing diagnostics/tests.

No deadline extension, second reload, progress/freshness bypass, new button,
permissions, parser changes, response reading, collector, upload or scan reset.
The explicit consent now also names document freshness metadata; the epoch is
never persisted or returned in a report. Same package/debug key/profile/history.
