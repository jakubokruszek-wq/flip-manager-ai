# 0.5.58 — opened-post SVG and CSS photo crops

## Reproduced gap

The opened-post reader selected only IMG elements, although the feed already handles single-image SVG and leaf CSS photos. A new complete synthetic structured Story -> exact photo proof -> SVG DOM -> viewport photos/commit regression fails on 0.5.57 with count=0, and passes with this fix. This is an independently reproduced code gap, not proof of the unknown Samsung payload format. The latest phone report had 12/12 opened/bound, text7/enriched4, zero detail crops, five NO_IMAGE outcomes.

## Change

Keep IMG extraction intact. Also consider single-image SVG and leaf CSS backgrounds using existing reviewed desktop-preview helpers. Both new types require an exact signed source URL from the document-scoped structured own-Story proof, even when an exact DOM card exists. SVG topology excludes text/foreignObject/shapes/multiple images; CSS excludes children/text/pseudo content/multiple URLs. Existing completed page resource or decoded matching image provides readiness evidence; no new resource load, Image(), fetch, media response reading or URI normalization is introduced. Resource readiness is not a claim that OCR will find text.

The rendered SVG root or leaf background element supplies geometry. Repeat proof, resource readiness, topology, source, visibility/occlusion and document checks after scrolling and before/after native pixels. Source replacement after capture sends drop, never commit. Existing one-image/post, max20, foreground consent, deadline, shared workers, RAM clearing, native commit/drop and MLKit OCR remain unchanged. No whole-card capture, text borrowing, new parser ownership rules, Manager connection/upload or production changes.

## Verification

Table regression covers successful SVG/CSS without any IMG, missing completed resources, overlay/multiple-image SVG, CSS text/pseudo content, unproved foreign sources, comment scope, occlusion and source replacement after pixels. Requests contain only bounded crop geometry and post slot; source URLs never leave the reader. Test harness makes Image()/fetch throw. Existing IMG tests and all parser/filter/queue regressions retained. App/instrumented compilation, JVM, isolation and APK signing required; long emulator intentionally skipped. Real Facebook/phone effectiveness remains to be verified by operator.
