# Gecko POC 0.5.11 — network-only identities must not disable viewport input

The Samsung 0.5.10 report has three exact IDs from NETWORK, no DOM records,
24 no-target waits, and zero native/thumbnail attempts. This is not evidence of
native wheel or screenshot failure: their DOM exact-link prerequisite prevented
both from being attempted. Previous local fixtures always supplied exact DOM
anchors, so their PASS did not cover the operator's layout.

## Correction

Standard wheel input requires the existing freshly consented, verified approved
group document and live native gate, plus a visible non-dialog/non-comment hit
inside a top-level group article or semantic feed/main. It no longer requires a
post permalink in that DOM. Input does not establish any post ID. Iframes, forms,
headers, navigation, sidebars, foreign post cards, and arbitrary widgets remain
excluded. Same 30-second/30-step/60-second trial budgets and three native no-op
failure cap apply. ACK is still not movement proof.

A private extension-only snapshot exposes the already parsed bounded network
projection and exact attachment evidence while transport remains active. It
requires the same nonce, top frame, tab, verified group, and original deadline;
it neither finishes the transport nor performs another network request. Only
normalized trusted media origins/paths and exact attachment IDs remain in the
extension. No media URLs or media IDs are sent to Android, persisted, logged,
placed in clipboard, or uploaded.

Visible image crops can match an exact parsed network attachment by media ID
or normalized resource URL even if the card has no post link. The post ID must
already come from the exact approved-group network record; image IDs are never
used as post IDs. Shared or conflicting evidence is rejected. Only matching
images are eligible, never neighboring arbitrary images or matching text.
Before commit, a fresh private snapshot must still confirm the association,
with unchanged source, viewport, geometry, loaded image, unobscured pixels,
current document and native gate. This proves attachment-resource association,
not a separately confirmed DOM post identity. No DOM identity is invented.

The same maximum 20 retained posts / 3 visible crops per post and RAM-only
lifecycle apply. Actual full galleries and all posts are not guaranteed.
There is no collector upload or production activation in this correction.

## Acceptance

Node regressions: no-permalink articles and empty semantic feed can receive
wheel; arbitrary widgets and dangerous hit targets cannot. Exact network media
can propose a crop without a DOM permalink; missing/shared/conflicting/remapped
media, changed sources and foreign cards cannot. Private snapshots require
verified context, refuse stale/wrong nonce/frame/tab/group/deadline, clear on
abort, and do not consume/finalize transport.

An additional actual GeckoView/Android scenario removes the initial exact post
anchor, obtains ID + attachment associations only from a local filtered HTTP
response, requires real native movement and a wheel-only new offer, and requires
two pixel-checked red/green thumbnails. Existing exact-DOM scenarios remain.
All tests use loopback fixtures, never Facebook. Physical Samsung remains an
operator check with fresh consent, foreground and screen on. No screen-off
success claim. Full-suite CI status and APK are recorded in PR #45.
