## Actual local thumbnail previews (new explicit consent)

Earlier Oferty showed only photo COUNT, not images. New consent explicitly covers
an ephemeral rendered Gecko-view frame in Android RAM for cropping already-visible
post images. No extra media requests, gallery clicks, media URLs or credentials
sent to Android. Source selected from exact single approved-group article using
existing media ownership checks. Loaded img/SVG only, minimum60px visible crop,
>=60% visible image, five-point occlusion check. No uncertain post/image match.

Native accepts only bounded nonce/request UUID/action and rectangle/slot metadata;
strict schema forbids text/URL/token extras. <=3 crops/frame, <=20 frames,20 posts,
3 slots each, <=192x144 bitmap per slot. Frame matches native view size and viewport
aspect within0.5%, <=4MP, <=800ms; crops inset2 physical pixels. Full frame recycled immediately after cropping.
Two-phase commit: crops remain pending until isolated content rechecks image node,
source, viewport dimensions/offset, geometry, occlusion and context. Changed/occluded/late image is dropped;
no received ACK alone attaches it to an offer. Pending crops expire and are erased
on bridge close/port/session loss. No encoding/files/cache/clipboard/upload.

Oferty displays cropped image bitmaps from bounded RAM, distinct from discovered
photo count. Missing crop is labeled honestly; not all gallery photos are visible.
On Android33+ disable OS Recents screenshots of this activity (manual operator
screenshots remain available).
Opening a post, starting another trial, pause/screen-off/context change/session
close clears ImageView drawables and recycles bitmaps. Aggregate history remains
count-only; existing38/34/30/22-stat histories decode without modifying their files.

## Native-input acceptance distinction

At the bottom of a finite feed, APZ can finish its wheel scroll decision before
a passive wheel listener appends more content. The wheel can unlock new data
without that first request moving. The finite-feed test therefore requires a NEW
wheel-only exact ID AND further measured movement beyond the original finite
range; ACK alone still cannot pass it. A SECOND real fixture has an existing deep
anonymous scroll range outside bounded DOM discovery. That test requires actual
measured nativeMoves>0, as well as the new wheel-only ID and red/green pixel crops.
Neither path invents successful native movement from an ACK. Both are required.
