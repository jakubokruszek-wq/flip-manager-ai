# Gecko POC 0.5.8 — bounded image evidence correction

Photo counts previously took max(media.length) per observation and only large
HTML img nodes. That misses smaller grid tiles and SVG image nodes, and cannot
accumulate distinct photos from partial responses for the same exact post.

Each extension model now keeps a private bounded set of exact media IDs and safe
normalized image URL aliases per post (20 posts, <=20 IDs and <=20 aliases each).
It unions observations within that model, strips URL query/fragment from keys,
deduplicates repeated media/renditions, reconciles URL-only aliases when an exact
ID later arrives, and clears the evidence with the model. Proven photo/media IDs
NEVER become post IDs. Only count leaves the extension; no media key/URL is added
to the native DTO, logs, history, clipboard or storage. Cross-model native merge
keeps the larger count instead of adding unknowable overlapping sets.

DOM accepts img and SVG image. A small >=80x80 tile needs a concrete photo-route
media ID inside its single exactly bound own article. Generic URI-only large
previews keep >=200x100 and approved Facebook/CDN URL constraints, reject profile/
other links and video-containing cards. Comments, nested foreign posts, avatars,
icons and unsafe media origins are excluded. No +N overlay guessed as total.
Network media must carry the unchanged core's exactAssociation/exactPostId proof;
direct video resources, unrelated/unverified media and deceptive hosts rejected.
Preview images can still be video thumbnails, so UI deliberately labels images/
thumbnails and says the complete photo count is unknown. No completeness flag.

No gallery click, navigation, image/gallery fetch or extra response budget. The
64-response/4 MiB budget previously reached on Samsung remains unchanged; missing
source data is not fabricated. No full post or media persistence/upload.

Node tests: multi-response identity union, size/query duplicate removal, alias
reconciliation, foreign/unverified/video/host exclusion, cap/clear, small grid/SVG,
comments/avatar isolation and no media-ID promotion. Actual local Gecko fixture
requires exactly three recognized photos from large img, small grid and SVG,
ignores a duplicate tile and comment image. Native UI asserts unknown-total label.
Existing scroll/focus/context/pause/link/privacy suites retained.

Install as update, keep profile/history. Compare the count with one actual post
containing multiple photos in the new-consent local foreground preview; a lower
count remains possible if Facebook never supplied all metadata within budget.
Pilot preparation is separate: see pilot/README.md. No production LIVE activated.
