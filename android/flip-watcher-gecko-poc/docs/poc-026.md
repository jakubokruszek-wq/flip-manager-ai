# Gecko POC 0.2.6 — desktop DOM path comparison and zero-candidate regression

Samsung report from 0.2.5: all diagnostic counts were zero while the operator could see posts. This proves the detector missed rendered content; it does not prove that Facebook exposes no DOM text or identifiers.

## What the desktop extension actually does
Reviewed from PR #45 base e462f8d66c6de23d15405e0cc8c3384dbe345972:
- `extensions/facebook-collector/content.js`: `visibleCards()` selects role=article; `collectDom()` uses the shared `parsePostLink`, requires exactly one unique post ID per card and looks for `data-ad-preview=message`, `data-testid=post_message`, `data-ad-comet-preview=message`. Search helpers also walk ancestors to find an exactly bound card.
- `collector-core.js` is the shared parser, not the browser DOM adapter. Bundling that file alone does not reproduce desktop collection.
- `network-hook.js` additionally wraps fetch/XHR and reads response bodies. This source can explain desktop success even when mobile DOM lacks exact IDs. It is NOT copied or activated: response-body capture remains outside consent/scope.
- Desktop collection also clicks/scrolls, merges records and can upload. None of these actions is invoked by this diagnostic.

## Change
Use the unchanged shared `core.parsePostLink` for identifiers, with explicit approved-group binding required before parsing. Unbound story_fbid, photo fbid, foreign groups and ambiguous multi-ID cards do not confirm an ID. No inferred alias between a slug and a numeric group.

Inspect the desktop message markers first, then mobile TextArea/Text/data-type=text. If no recognized message or article exists, traverse at most 5000 text nodes in the rendered DOM and retain at most 2000 candidate text blocks temporarily. No price/area requirement and no requirement for a leaf MContainer. Analyze at most 20 candidates; candidate blocks do NOT prove 20 separate posts.

New local provenance counts: desktopMessageBlocks, mobileTextBlocks, fallbackTextBlocks, visibleTextBlocks, ambiguousCards. Fallback blocks are explicitly heuristic. The existing field heuristics remain count-only. No raw text, link or ID crosses the native port or enters files/logcat. All text references are temporary inside this synchronous read. No storage, scan, scrolling, clicks, inline script extraction, response interception or upload.

Consent, exact current group, visible document and STOP on LOGIN/CAPTCHA/CHECKPOINT/unavailable group, navigation, hidden document/session interruption remain required. Each attempt needs fresh consent. Query/fragment contexts remain conservatively refused outside fixtures.
