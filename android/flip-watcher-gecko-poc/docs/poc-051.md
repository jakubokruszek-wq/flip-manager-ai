# Gecko POC 0.5.1 — repair the desktop feed path

## Physical result and what it proves

Samsung 0.5.0 reported desktop=1, verified=1, one navigation, one unique exact
ID, 16 completed bounded responses / 1,198,998 bytes, no stream/decode errors,
no structured records, and zero successful moves out of five attempts. Seven DOM
observations were repeated reads of one ID, not seven posts. No usable offer was
established: physical NO_GO. The received bytes do not prove post payloads existed.
The limit excluded nine additional response attempts; completeness is not claimed.

## Changes

The desktop extension selects a scroll container from the document and semantic
feed containers; the POC incorrectly scrolled only window. It now considers the
same feed selectors and at most eight ancestors of bounded top-level articles.
Only visible, connected, actually scrollable overflow containers containing an
article qualify. Dialogs/comments/hidden or clipped widgets are excluded. The
root remains preferred when it is actually scrollable. A freshly loading feed
gets at most 2.5 seconds to develop scroll extent, under the original total deadline.
Five moves remain the hard cap; movement is measured after the rendering pause.
No manual interaction, click, URL change, security bypass or limit increase.

The POC also omitted the desktop extractor's data-ad-rendering-role=message
selector. It now reads that exact message marker with the three existing ones,
within the same exact-ID-bound article, excluding nested articles/comments.
Identical nested markers are one message; distinct texts remain ambiguous. It
never falls back to whole-card text, comments, neighboring posts or account data.

Identity-only UNKNOWN observations no longer poison a concrete sale intent when
layers merge. Two conflicting concrete intents still remain permanently unusable.
Numeric/location conflicts retain their existing conservative clearing behavior.

The local report labels DOM reads as repeated observations, and warns about zero
movement and exhausted response limits. No new raw-data export or weaker ID rule.
The response allowlist/parser and all response/consent/storage limits are unchanged.
Network/hydration absence on this Samsung is still unexplained; not declared fixed.
