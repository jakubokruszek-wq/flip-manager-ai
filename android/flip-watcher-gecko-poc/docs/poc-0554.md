# Gecko POC 0.5.54

Phone 0.5.53 completed 9/9 openings, 5 texts, 4 enrichments and 9 worker closes, but all 9 detail-image checks remained NO_PROOF. This does not establish the real media shape; existing synthetic proofs did not validate the phone's skipped images.

The existing network-media adapter supports typed Photo and Image and direct attachment URI renditions; the detail-photo selector lacked those variants. The selector now accepts direct HTTPS fbcdn URI on typed Photo/Image only within an inherited attachment/media/photo boundary of the existing validated own Story. Actual loaded IMG dimensions, exact currentSrc/src, unique article and two-phase crop proof remain mandatory. Unattached Image, foreign Stories, user/page/comment entities and actor/author/owner/profile/avatar branches cannot supply pictures. Known attachment UI strategy/renderer names are treated as containers rather than Story entities; explicit conflicting post IDs and foreign post links still reject them. Other unknown Story types remain blocked. No expected-URL-only identity, URI query stripping, fetching, extra image budget or whole-card capture.

Document-local count-only stages now distinguish NO_MEDIA_DATA (no typed Photo/Image in analyzed valid selected JSON), NO_RENDITION (typed media but no supported safe URI), OWNER_FILTER (rendition present but no accepted source) and legacy NO_PROOF (no detailed cached proof). These are stages of the bounded reader, not proof that the page/post contains no media. No data values or type names are exported. Native fixed-outcome validation and aggregate sums/20-check limits include the new codes. Old exact nine-outcome history maps remain accepted and are zero-filled for new categories; partial/unknown maps are rejected.

Single-post workers, property extraction, original deadline, fresh foreground consent, unsafe-failure RAM clearing and no-upload/no-persistence rules remain unchanged. Manifest/app/report version 0.5.54.

Tests cover direct Photo/Image URIs, attachment-only Image, author/owner/comment/shared exclusions, UI strategy containers, conflicting numeric owners, unknown Story entities, distinct stage diagnostics, old history compatibility and loaded-image -> crop/commit for new variants. No real Facebook/Samsung test by agent; no claim that every observed NO_PROOF is fixed. Native long emulator execution intentionally skipped per user preference.
