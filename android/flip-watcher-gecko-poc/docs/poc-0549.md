# Gecko POC 0.5.49 — bounded detail-worker sessions

Physical 0.5.48 confirmed 9 posts and read text from 6 before ENGINE_KILLED at 10/12 openings. This validates extraction on the phone but not complete offers. Gecko's kill event does not establish OOM, memory pressure, or another root cause.

The detail queue now uses one visible temporary GeckoSession for at most three posts. Each worker is deactivated, detached and closed before the next is opened. Its navigation/progress/content delegates and native-message handler are detached. A 250-ms coroutine delay between workers lets pending native cleanup run; it does not prove an OS renderer process was reclaimed. The original group session stays inactive and unchanged until the whole attempt exits; it is restored on final completion/cancellation. One original plus one open worker is the API-level invariant, not a renderer-process count claim.

One ReviewDataGate, original queue, merged RAM result map, unbound streak and three-minute deadline span all batches. Worker rotation never restarts the grant or retries after ENGINE_KILLED/CRASHED/context loss. Exact URL/group/post/port generation and fresh per-read nonce checks remain. Every native worker callback is scoped to a generation; a closed worker cannot modify the next worker's gate. Only a fresh authorized worker may accept its initial blank document. Two consecutive unbound posts still stop across a batch boundary.

CollectorChannel.close is terminal/idempotent, unregisters its session-scoped extension message delegate and rejects late connections. It does not uninstall the extension, clear cookies/profile data or affect another session's controller. Original settings/history/outbox/quota are unchanged; per-post purgeHistory remains confined to the worker.

Reports optionally carry bounded session-open/close call counts (0..7, closed <= opened, opened <= ceil(selected/3)). Old histories remain readable. OCR reports display the same counters. They describe completed session API calls, not proof of renderer memory release. Unsafe failures still clear RAM previews; no content/ID persistence or silent partial-result publication is introduced. Combined OCR + opening still shares the existing image/time limits and one combined fresh consent.

Validation: existing Node suite; JVM cases exercise stale generations, new-worker initial blank handling, shared deadline, concurrent-worker rejection, no recovery after kill, strict batch counters and legacy/nested OCR histories. Added local Android fixtures cover seven posts across three workers and cancellation between batches, with original-session restoration; they are compiled but emulator execution is skipped per user preference. Existing extraction/selector code is unchanged. CI app/instrumented compilation, JVM, isolation, signing/package checks remain mandatory.

A complete result should report all those sessions closed. This is a resource-lifetime mitigation, not a proven fix for the earlier engine kill; actual Samsung behavior requires verification.
