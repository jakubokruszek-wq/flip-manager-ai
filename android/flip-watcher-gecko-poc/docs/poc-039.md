# POC 0.3.9 — statyczny JSON w znanych opakowaniach dokumentu

Nowa wersja uzupełnia konkretną różnicę względem desktopowego collectHydration.
Tryb „Dokument grupy • lokalnie” przyjmuje również CAŁE skrypty o postaci
`require("ServerJS").handle(JSON);` lub `new ServerJS().handle(JSON);`.
Argument musi być kompletnym obiektem/tablicą JSON. Parser nie wykonuje skryptu,
nie wywołuje require/ServerJS, nie używa eval/Function i nie pobiera skryptów src.
To wąska gramatyka, nie ogólny interpreter JavaScript. Nieobsługiwane opakowania,
wyrażenia JS, funkcje, dodatkowe instrukcje, argumenty i komentarze są odrzucane.
Dotychczasowe application/json nadal działa.

Każda próba wymaga nowej zgody z jawnym opisem rozszerzonej analizy dokumentu.
Te same limity: jeden dokładny dokument grupy, 25 s, 2 MiB, pierwsze 64 skrypty,
512 KiB/skrypt, 20 dokładnych ID z jawnym permalinkiem zatwierdzonej grupy.
JsonBlocks oznacza teraz poprawne bloki JSON także wyodrębnione ze znanych opakowań.
Dedup, ścisła tożsamość, brak zapisu/eksportu surowych danych i STOP bez zmian.
Cena/metraż to nadal heurystyki. Nie czyta XHR/Beacon/innych odpowiedzi w tym trybie.
Nie uruchamia skanu, kolektora, backendu ani produkcji, nie zmienia UA.

Weryfikacja: nowe regresje odtwarzają pominięty format i przypadki fałszywych ID,
typów, src, wyrażeń, limitów i anulowania. Istniejący rzeczywisty test dokumentu
na emulatorze używa dodatkowego syntetycznego rekordu ServerJS; oczekuje teraz
3 poprawnych bloków JSON i 2 dokładnych ID, zamiast 2 bloków i 1 ID.
