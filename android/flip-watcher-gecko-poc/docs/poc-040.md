# POC 0.4.0 — jeden link operatora, lokalne rozwiązanie przekierowania

Przesłany przez operatora link ma postać /share/p/TOKEN/. TOKEN nie jest ID posta.
Nowa funkcja „Narzędzia / raport → Sprawdź udostępniony link” otwiera jeden ręcznie
wklejony link w istniejącej sesji GeckoView. Nie używa zewnętrznego resolvera,
backendu, zapytań HTTP aplikacji ani publicznego proxy. Dotychczasowy podpis/pakiet.

Każde uruchomienie wymaga NOWEJ jednorazowej zgody z opisem przejścia poza stronę
główną grupy. Pole wejścia nie ma zapisu stanu/autofill i jest czyszczone po zamknięciu.
Brak automatycznego czytania schowka. Brak zgody oznacza brak nawigacji.

Do 20 s i 8 żądań nawigacji. Tylko HTTPS facebook.com/www/m; bez portów,
credentials, fragmentów i query. Dozwolone wejście /share/p/[A-Za-z0-9]{6,40}/.
Tylko dokładne /groups/lodzsprzedazzakupwynajem/(posts|permalink)/[0-9]{5,30}/
może dać potwierdzenie. Host może zmienić się w ramach tej samej allowlisty.
Odrzucane: inne/niezweryfikowane numeryczne grupy, profil, zdjęcie, generic ID,
zmieniony token share, nowa karta, ręczne przejście, nieprzekierowane kolejne
żądanie, JS/meta-refresh zamiast obsługiwanego przekierowania HTTP. Nie rozszerzamy
przy tej okazji ogólnej polityki grupy ani uprawnień rozszerzenia.

Native wiąże location z ostatnim dozwolonym żądaniem i nowym portem rozszerzenia
(sender URL == aktualny adres). Stary port nie może potwierdzić nowej strony.
Dopiero końcowy, bezpieczny, w pełni załadowany dokument potwierdza adres.
Kontrola bezpieczeństwa w skrypcie izolowanym: adres, widoczność, readyState,
tytuł oraz obecność formularzy login/hasła/CAPTCHA/checkpoint. Bez treści postów,
skryptów, wartości atrybutów, odpowiedzi sieciowych i parsera kolektora.
MutationObserver + visibilitychange + kontrola URL co 100 ms przerywają aktywną
kontrolę; pauza/wygaszenie, błąd/awaria/zamknięcie sesji, nieoczekiwana utrata
portu lub niezgodny redirect: STOP i czyszczenie. Utrata starego portu jest
oczekiwana wyłącznie podczas dozwolonej nawigacji do nowego dokumentu, nadal
w jednym 20-sekundowym budżecie. Brak samowznowienia i ponawiania.

Wynik LINK 0.4.0: status, stały kod przyczyny, liczba żądań, 0/1 potwierdzonych ID.
Żadne ID/URL nie jest zapisywane w wyniku, historii, preferencjach czy pliku.
Przeglądarka używa dotychczasowego profilu i jego standardowej pamięci podręcznej jak przy ręcznej nawigacji; nie obiecujemy globalnego wyłączenia zapisu cache Gecko.
Nie dodajemy jego ścieżki do navTrace, a standardowy panel ukrywa adres/tytuł/DOM
w czasie tej próby i pokazywania wyniku. Powrót do grupy kończy ten kontekst.
Istniejące cookies pozostają w profilu Gecko; nie są odczytywane ani eksportowane.

CONFIRMED oznacza potwierdzony dokładny adres posta zatwierdzonej grupy, nie
weryfikację treści/dostępności/kompletności oferty i nie działający skaner.
Przekierowanie do numerycznej grupy pozostaje UNVERIFIED_DESTINATION, dopóki
jej tożsamość nie zostanie niezależnie zatwierdzona. Link z parametrami lub
inny format docelowy jest nieobsługiwany; nie zgadujemy tożsamości.

## Test Samsung (dopiero po CI)

Zainstaluj arm64 jako aktualizację, bez odinstalowania/resetu. Konflikt podpisu:
przerwij. Włączony ekran, otwarta zatwierdzona grupa, załadowana strona i port.
Narzędzia / raport → Sprawdź udostępniony link → wklej swój link → przeczytaj
nową zgodę → „Zgadzam się — sprawdź”. Nie dotykaj strony do wyniku, maksymalnie
20 s. Raport LINK 0.4.0 skopiuj bez adresu, treści posta i danych konta.
Osobna próba STOP: po nowej zgodzie wygaszenie ma zakończyć próbę i wyczyścić wynik;
bez automatycznego wznowienia po odblokowaniu. Nie deklarujemy pracy pod blokadą.

Bez automatycznego otwierania prawdziwego linku przez agenta, bez skanu/kolektora,
LIVE, zmian produkcji/PR44, merge i deploymentu. Przy CONFIRMED: CONDITIONAL GO
dla ręcznie dostarczonego jednego linku. Automatyczny skaner nadal NO_GO.
