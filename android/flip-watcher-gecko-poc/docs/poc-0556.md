# Gecko POC 0.5.56

Phone 0.5.55 completed 11/11 openings and closes but captured zero detail images. Ten attempts were OWNER_FILTER, with excluded paths flagged in ten and unbound Story sections in five. Flags can include unrelated media, so they do not prove the exact real payload type.

## Reproduced defect and fix

The detail selector used /story|post/ to classify media boundaries. A GraphQL StoryAttachment node was consequently treated as an independent Story and rejected when it lacked a post ID. When it had a numeric attachment ID, that ID was instead mistaken for a foreign post ID. A differential test demonstrated that the existing networkMedia adapter accepted a photo under StoryAttachment while the detail selector rejected the same source. That test failed before the fix and passes after it.

Media ownership now distinguishes post entities from the StoryAttachment family of attachment containers and Comet attachment strategies/sections/renderers, only inside an inherited attachment/media boundary. Attachment and Photo/Image generic IDs remain media/container identifiers and cannot establish a post. Explicit post-id metadata on those nodes is only a consistency constraint: it must match the already validated own post, conflicting fields reject. Foreign post links on media or attachment nodes are checked independently of type.

The selected numeric own Story and actual approved-group source permalink are still required before any image source can be accepted. URI matching, document scope, actual loaded/rendered dimensions, unique article, occlusion and two-phase viewport commit remain unchanged. No expected-URL inference, opaque-ID decoding, arbitrary page capture, fetch, global reference join or foreign-data borrowing. Data-field extraction and single-post workers/engine guards are unchanged from 0.5.55.

Validation covers multiple attachment types with missing, numeric and opaque attachment IDs; differential comparison with existing networkMedia; matching/conflicting explicit post metadata; absence of root owner/permalink; foreign URLs; author/comment/shared branches; unrelated sibling payloads; and full detail source -> loaded image -> crop/commit for a numeric-ID StoryAttachment without a DOM header permalink. Existing price, area, intent and privacy regressions remain.

This is a functional attachment-identity fix. It is not proof of success on the phone's unknown payloads. Long emulator execution intentionally skipped per user preference; no real Facebook/Samsung test by agent. Same Draft PR45 only, no production scan/collector, upload, backend change, merge/deployment, uninstall or clear-data. Fresh foreground consent and all original limits/unsafe-failure clearing remain.
