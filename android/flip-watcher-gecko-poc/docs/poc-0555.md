# Gecko POC 0.5.55

Phone 0.5.54 reported 7 OWNER_FILTER detail-image attempts with zero new crops, then ENGINE_KILLED at 8/9 openings. Seven identities/two texts/two enriched rows had been confirmed. This release does not relax source ownership or claim that renderer termination is fixed.

## Specific rejection diagnostics

Each validated document proof retains six count-only flags from analyzed valid JSON: excluded comment/author/video path or semantic type; foreign/conflicting numeric identity or post link; unbound Story boundary; unmatched opaque section identity; undersized rendition metadata; no selected own data scope. Flags are per attempt and may overlap, including unrelated media in the same analyzed blocks. They do not identify a unique cause for an intended photo or prove no data exists.

Optional `filters` in image replies contains only the complete fixed six-key 0/1 map. Native code validates exact keys and integer bounds; malformed maps stop as protocol failures. Aggregate image history includes the flags with each <=checked<=20; main outcomes alone still sum to checked. Both old complete outcome schemas remain readable with zero-filled new flags. No raw paths, type names, IDs, source URLs or post text are exported/persisted.

## Engine callback handling

Original activity title/crash/kill callbacks now require the callback session to be the current original session. Retired-session callbacks cannot clear or close a newer session. Original delegates are removed before native close. Worker callbacks keep the existing epoch guard. Current original or worker engine loss still stops and clears RAM; there is no automatic recovery or data persistence.

Reports retain ORIGINAL_ENGINE_KILLED/CRASHED versus WORKER_ENGINE_KILLED/CRASHED, identifying the session callback that stopped the attempt. Sessions may share a content process, so this is not an OS process ID or a kill/OOM cause. Old generic engine reasons remain readable.

Property extraction, image selection/identity rules, one-post workers, fresh foreground consent, shared time/image/post budgets and production isolation are unchanged. App/extension/report version 0.5.55.

Validation includes all six rule flags with privacy assertions, strict optional map/overlap/bounds/history compatibility, engine-origin roundtrip/no gate restart, and a native retired/current callback fixture (compilation only in the fast lane). Long emulator execution intentionally skipped per user preference. No real Facebook/Samsung test by agent.
