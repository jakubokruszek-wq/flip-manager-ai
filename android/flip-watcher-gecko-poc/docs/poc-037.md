# POC 0.3.7 — osobno zatwierdzony dokument grupy

Fizyczny raport 0.3.6: FastScroll=1, CadenceMs=500, Steps/Moves=5,
LoadMode=0, 17 zdarzeń (16 obrazów, 1 media), brak endpointów danych i bajtów.
Przewijanie działa; ten pomiar nie obejmował otwarcia grupy. Nie potwierdza
braku postów. Beacon pozostaje NO_GO i jest zablokowany poza fixture.

## Nowy zakres

Narzędzia / raport → **Dokument grupy • lokalnie**. Domyślnie OFF,
bez zapisanej preferencji. Nowy jednorazowy dialog, anulowanie bez odczytu.
Jedno dokładne przeładowanie bieżącej zatwierdzonej grupy w tej samej karcie;
okno 25 s obejmuje ładowanie. Bez automatycznego przewijania. Dotychczasowe
zgody DOM/XHR/skanu nie obejmują dokumentu i nie są wykorzystywane.

Filtr czyta tylko ten main_frame: maksymalnie 2 MiB; pozostałe odpowiedzi,
XHR/fetch/other/Beacon/ping/skrypty/obrazy nie są odczytywane. Oryginalne bajty
są najpierw przekazywane stronie bez zmian. Żadne nagłówki, payloady żądań,
pola logowania ani API cookies nie są czytane. HTML może zawierać dane sesji;
pozostaje przejściowo w RAM, parser nie wyodrębnia cookies/tokenów, niczego
nie zapisuje ani nie przesyła. Po anulowaniu/końcu bufor i zbiory ID są zwalniane.

Analiza dopiero po potwierdzeniu bezpiecznego nowego dokumentu. Dokładne linki
grupy w anchor href są liczone osobno (max 400 sprawdzonych, 20 unikalnych),
po usunięciu komentarzy i skryptów. To lekki ograniczony parser, nie pełny
parser HTML; liczba linków nie jest potwierdzeniem pól oferty. Dane strukturalne
wyłącznie z poprawnych bloków script type=application/json bez src:
max 64 sprawdzone bloki, 512 KiB/blok. Nie wykonujemy kodu skryptów.
Niezmieniony parser desktop wymaga dodatkowo jawnego dokładnego permalinku
grupy; same post_id, obce grupy, tekst i dowolne skrypty nie potwierdzają ID.
20 unikalnych ID, deduplikacja. Cena i metraż nadal sygnały heurystyczne.
Nie ma gwarancji, że Facebook umieszcza rekordy właśnie w takim JSON.

Na wyjściu tylko 86 ograniczonych liczników. Nowa linia Dokument grupy:
Read, Completed, Bytes, JsonBlocks, Permalinks. responseExactIds oznacza
strukturalne rekordy z jawnym linkiem; Permalinks nie są do nich dodawane.
Brak skanu, kolektora, zapisu treści/ID/adresów, uploadu i backendu.

Druga nawigacja/redirect/inny dokument, LOGIN/CAPTCHA/CHECKPOINT, utrata
kontekstu/portu, pauza/wygaszenie: STOP i wyczyszczenie. Bez samowznowienia.
Dokument >2 MiB lub błędny UTF-8 nie daje częściowych rekordów. Wykrywanie
challenge jest konserwatywne i może zatrzymać również dokument z takim markerem.
