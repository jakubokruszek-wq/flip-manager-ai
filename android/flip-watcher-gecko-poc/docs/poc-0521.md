# 0.5.21: accessible notification names and explicit refusal reasons

The physical Samsung0.5.20 report is NO_GO/NOTICE_BLOCKED, noticeDetected0 and
noticeClosed0. This proves no known notification notice was recognized. It does
NOT identify the actual modal, its label, or whether the failure was a name,
multiple windows, a limit, or a security dialog. Production/pilot remains off.
We do not claim a physical root cause from this aggregate.

Review found missing standard variants: recognition required one of four exact
aria-label values on role=alertdialog.0.5.21 resolves a known name through
aria-labelledby (up to2 references, same connected document and INSIDE the
checked modal), also accepts role=dialog, and recognizes the EXACT English
notification instruction published in Mozilla1926869 when no known name exists.
A generic Close, notification keywords or similar prose are never sufficient.
No invented localization phrases are added. The original four exact names stay.

Before text classification the modal must not own/contain a post, feed, form,
input, editable, link or frame. Only at most200 DOM/text nodes and1024 characters
are inspected transiently; no complete page/post text is read by this helper.
Security/authentication words in the name or bounded message refuse the action,
even if it also contains the exact notification instruction. References outside
the modal or oversized/ambiguous content fail closed. Existing one visible
modal/one visible unobstructed Close, fresh consent/context, one ordinary click,
1500ms/original deadline, no permission grant/CSS edit/node removal rules remain.
The deadline is rechecked immediately before click.

Four new fixed scalar fields: noticeReason(0..12), noticeModals(0..64),
noticeVisible(<=modals), noticeNameSource(0..3: none,label,heading,exact instruction).
No raw labels, reference IDs or message text are exported or persisted. Existing
82-field history is padded in RAM, without rewriting/deleting it. The short
NOTICE_BLOCKED report gives the actual refusal category and context facts;
it does not emit50 placeholder zeros or a false no-scroll-container warning.
Remaining counters were not collected for the final report, not proven zero
network activity. Temporary buffers are discarded. No offer rows on STOP.

Regression tests cover actual window input for the old labelled alert,
role=dialog+aria-labelledby, generic-name+exact instruction, and a security
label that MUST remain untouched despite containing the same instruction.
Known variants must close normally, allow a real swipe, continue>=25 moves
and extract a newly loaded exact fixture offer. All pages are localhost.
Node also covers similar prose, external/foreign refs, oversized text,
post-owned text refusal and the immediate deadline recheck. JVM covers audit
bounds, old82-field history and a short truthful STOP with verified context.
The workflow runs these4 focused cases, then the FULL Android suite.

Physical validation still requires a new operator-consented Samsung trial.
This change fixes documented implementation gaps; it does not assume the
unseen phone modal uses one of them. If it still stops, the fixed refusal
reason/counters are required before any further behavioral change. Never
broaden to clicking arbitrary Close buttons. No login/CAPTCHA/checkpoint
handling, real agent Facebook test, upload, production services, merge,
deployment, paid infrastructure or old scan/outbox/history reset is performed.
CI results and update APK are linked in PR45 after verification.
