## Correction

A topmost hit can be an ordinary ancestor of a visible post card rather than its
child (for example rendered pointer-events:none post contents). Region binding
now also accepts that relationship, requiring all of:
- same connected document, existing dialog/comment/form/frame/chrome guards;
- a safe top-level card, with no foreign group permalink;
- positive visible card geometry containing the sampled point, within the same
  existing10–90% viewport range and64-probe budget;
- computed pointer-events:none and actual contains() plus a parentElement walk capped at64, refusing points clipped by an ancestor;
- no known unsafe/foreign card under the shared hit parent;
- no independent nested overflow widget.

No sibling overlay, arbitrary coordinate-only target, element underneath the top
hit, iframe document or synthetic identity becomes trusted. Existing semantic
regions and moved-feed descendant path are unchanged. Actual rendered movement,
not request ACK, remains required.

Image readback likewise recognizes a real ancestor as the top hit only when
computed pointer-events on the image is none and the image is visible. It checks
all five points and actual bounded ancestry, same document and sensitive region
exclusions, both before capture and before commit. Sibling overlays, foreign or
hidden/detached/reparented images fail closed. Existing exact post/media binding,
geometry/source consistency,3-slot RAM limit and pixel checks remain.
