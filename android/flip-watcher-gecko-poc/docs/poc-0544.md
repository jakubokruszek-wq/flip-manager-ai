# Gecko POC 0.5.44 — explicit manual-review opening

Physical 0.5.43: enrichment opened two of eleven posts, bound none and stopped NO_OWN_POST. Separately the original content process was killed. These are distinct events; the report does not prove absence of listing data or the cause of the process kill.

Manual-review cards now have a full-size “Otwórz post do sprawdzenia” button, in addition to the exact permalink. Explicit clicks on a current review row open the validated exact permalink in the existing visible authenticated GeckoView, not via an external Android intent. Showing the list never navigates, grants OCR consent or starts enrichment. The prior local preview is erased before intentional navigation, just as for existing offer links; stale cards cannot reopen a post. Eligible-offer external-link behavior remains unchanged.

Exact approved-group post URLs have a distinct APPROVED_POST view-only classification, so they are not incorrectly presented as another group. This classification never permits group scanning, response reading, OCR, or automatic data extraction. Credentials, explicit ports, query/hash, unknown aliases, other group routes and invalid IDs do not receive it. The existing native navigation/security handling remains active.

A NO_OWN_POST enrichment failure can preserve only the original group preview when the caller still holds the same session/list and the Activity is resumed on the approved group without a halt. It never publishes unverified detail rows. Other context, pause, close and engine failures still erase the data. Failure reporting no longer claims NO_OWN_POST always erased the original preview; an active retained preview returns to Offers with a clear message.

This fixes manual access and avoids unnecessary data loss in a safe unchanged session. It does not claim automatic detail binding is fixed: NO_OWN_POST is still a supported refusal; no weakening of article/comment identity evidence.

Validation: 509 Node tests; CI app/instrumented compilation, JVM, isolation, signed APK. Long emulator execution skipped per user preference; modified Android button tests are compiled, not executed in this lane. Actual Facebook opening requires Samsung verification. Install as an update, run a fresh group preview, open Offers and use “Otwórz post do sprawdzenia” under an individual review card; the top “Uzupełnij” action is the separate automated attempt.

No merge, production deployment, collector activation or upload. Existing one-scan quota/history/outbox remain unchanged.
