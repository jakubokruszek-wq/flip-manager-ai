This patch preserves the 0.5.29 scroll, keyboard, consent and stop rules. It adds a bounded pass over at most 500 already-rendered HTML IMG elements outside all semantic articles, within feed/main. A source must match an unambiguous attachment URL or numeric photo-route media ID from an existing exact network post record, and that post must remain retained. Conflicting ownership, profile/external links, foreign posts, comments, dialogs, video, forms, unloaded, small (below 200×100 CSS px), offscreen and occluded images are rejected. Identity, source, containment, geometry and current network ownership are checked again before committing the existing RAM crop. No new fetch, media download or response type is added. At most three images per post, existing total limits unchanged. Global SVG/CSS extraction is not added.

Native messages contain crop rectangles and exact retained post identity, never source URLs. New persistent report counters contain only numbers: document IMG inspected/bound/selected. Old 109-counter histories are padded in RAM without rewriting history. Already available RAM thumbnails also appear in the manual-review section; this does not qualify those posts as offers. Pause/context change removes previews. No OCR: fields drawn into a picture remain unknown.
