## Data correctness

A reproduced operator example, `Sprzedam mieszkanie Łódź ul. Różyckiego 45,8 m2 260 000 zł`, incorrectly produced 2,260,000 zł: the ASCII unit's 2 joined the next numeric price. The POC-only notation adapter now delimits square-metre tokens before the unchanged pinned price rules. It preserves ASCII/Unicode spelling and existing Unicode-area preference (e.g. rounded 65m2 versus precise 64.98m²). A separate address input removes area tokens so the area cannot become a false house number. Real explicit house numbers remain eligible.

An explicit sale with Polish M2..M6 apartment shorthand followed immediately by one bare area, such as `Sprzedam M3 40m ... 355 tys`, may normalize that area to m². It requires 10..300, a unique candidate, no competing explicit area and no immediate distance wording. Bare arbitrary distances and multiple shorthand candidates stay unfilled. This is a POC notation adapter only: upstream property sources, their pin file and collector-core are unchanged. No guessed location/price/rooms or OCR auto-promotion is added.

## Image handling and report

Own typed Photo proofs also recognize large_share_image and thumbnail_image renditions, with the same exact source URI, dimensions, document scope and foreign-ancestor rejection. No fetch, URL normalization or identity relaxation.

Each detail-image attempt returns exactly one fixed outcome: captured, no ownership proof, no eligible image, unloaded, geometry/occlusion, missing ACK, ambiguous ownership or context stop. Native code strictly validates nonce/shape/status/count/reason. Malformed replies are protocol failures. Count-only aggregate history adds an optional complete map, up to 20 checks with sum matching checked count; old summaries remain readable. It contains no IDs, URLs, text or images. The map is shown before the long parser diagnostics. Counts describe detail-image selection, not cached OCR or absence of data. Active context/engine failures still halt and clear RAM.

Fresh in-app consent, foreground, 20-image/20-post limits, original three-minute deadline and single-post session scheduling remain unchanged. No retry after engine loss, no persistent business data, no production scan/collector, upload, merge or deployment.

Validation covers price/unit adjacency, address-versus-area separation, explicit-address retention, shorthand versus distances/ambiguity, exact image outcomes and alternate Photo renditions; JVM covers strict image reply protocol, legacy/count history and the combined 4096-byte history limit. Long emulator execution is intentionally skipped per user preference. No real Facebook test or complete extraction guarantee is claimed.
