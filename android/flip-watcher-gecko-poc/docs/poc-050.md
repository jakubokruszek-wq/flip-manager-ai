# Gecko POC 0.5.0 — one desktop-mode local acceptance trial

## Why this is a different path

Physical mobile-mode runs through 0.4.3 have not established usable post identity.
The desktop extension works by combining DOM, hydration and passively observed
fetch/XHR data; the POC still used default mobile Gecko settings. The new explicit
trial uses Gecko's standard USER_AGENT_MODE_DESKTOP and VIEWPORT_MODE_DESKTOP,
without a fabricated UA string, about:config, remote debugging or security bypass.
No share-link resolver is involved. No production collector is activated.

This version provides actual selected local rows, not only another set of counters.
It does not assert Facebook will deliver the desktop data on the physical Samsung.
The operator's one physical trial is the architecture acceptance gate.

## Reused code and boundary

- Existing collector-core.js remains byte-identical to its reviewed SHA256.
- The existing response transport factory is reused in a separate tab-bound
  instance. Legacy instances retain 25 s / 8 responses / 512 KiB / 2 MiB / 4 streams.
- The new desktop-only instance, enabled by fresh desktopConsent, has a 60 s TOTAL
  monotonic budget including arming/loading, at most 16 bodies, 2 MiB/body, 4 MiB
  aggregate and 8 concurrent streams. Only approved-group top-frame fetch/XHR/other
  endpoints; no Beacon, document-body filter, headers, cookies or form payloads.
  Original bytes are forwarded first and never rewritten. New limits cannot be
  requested by legacy messages; only the private desktop constructor enables them.
- Capture is armed on the old approved document BEFORE desktop navigation. Initial
  responses are queued in bounded background RAM until the fresh document is safe.
  Only same HTTP request-id redirects between known hosts of the same approved
  group are accepted before verification. Another document, group or source stops.
- Native code requires the approved request/location, new trusted port generation,
  nonce, fresh document timeOrigin, desktop UA settings/string and desktop layout.
  No stale port, history-only address, unverified alias, media ID or guessed post ID.
- An isolated content module combines own-message text of unambiguous top-level
  article cards, bounded script data and exact network records. Nested/foreign cards
  are rejected. Exact identity and the heuristic offer fields remain distinct.
- Pure existing price/room/intent/location rules are generated with Node's built-in
  type stripper. scripts/desktop-fields.cjs --check pins FOUR untouched upstream
  files and compares generated code. No server imports, geocoder, Vision, paid API
  or new regex price fork. Fees/current-vs-potential room counts and explicit other
  cities retain the existing rules. No full backend normalization is claimed.
- At most 20 unique IDs in local projection. Duplicates merge across layers. Conflicting
  non-null price/area/location fields are cleared, not guessed. Only selected numeric/
  bounded fields, exact IDs/permalinks and photo COUNTS leave the extension for native RAM.
  No post text, author, media URLs, cookies or token is sent to native or persisted.

## UI and privacy

The main browser still has the same three children and most of the screen.
Tools starts with only the new trial and its result; old tools/history are retained
under a collapsed archive. Existing scan flags, histories, outbox and receipts are
not reset or migrated. Same applicationId and public test signing key; update only.

The new consent describes the one reload, desktop mode, data sources, response/RAM
limits, 5 scrolls, 20 IDs, 60 s TOTAL, visibility STOP and safe aggregate persistence.
It is never restored or reused. Closing the session resets browser settings through
creation of the next default mobile session; cookies/profile remain as before.

A single automatic result dialog contains selected rows with exact IDs/permalinks
and heuristic fields. No local offer/database record is created. Copy report copies
ONLY fixed status and aggregate counts, not the rows/IDs. The separate private
summary preferences contain only verdict, fixed reason, bounded counts and navigation
count; schema rejects additional data. Rows and displayed text are cleared on pause,
context change or session close, and never restored. No preview upload or background
scan. Verification markers abort immediately and discard partial data.

## Acceptance tests

Node tests cover fields reused from production rules, exact identity, fee-vs-price,
potential room count, other cities, 20-row cap, duplicate enrichment/conflicts,
header/body/Beacon exclusion, initial queued data, byte forwarding, consent revocation,
isolation, 60 s limits and cancellation/cleanup during scrolling. Existing tests run too.

JVM tests cover consent, request/location gating, redirects, gestures/new windows,
original deadline, late callbacks, protocol/schema/type/range validation, raw-data
rejection, aggregate privacy, non-sale exclusion and history validation.

New Android16 test uses the SAME DesktopSessionPreview runner as PocActivity.
A local HTTP server serves a blank mobile placeholder and a desktop feed at the SAME
URL, based on the actual built-in User-Agent it receives. The desktop page makes an
initial fetch in its head before the new content script starts, plus hydration and
own-card DOM data. The test checks actual desktop UA/layout, initial network bytes,
three unique identities, merged layers, price/area/rooms/photos and exclusion of a
purchase request. A second freshly consented run introduces a real verification
mutation and must discard partial results. Another UI test checks transient rows,
count-only clipboard and preferences, pause/recreate cleanup and preservation of the
old one-shot flag/link history. New class runs focused first, then full suite.
Every HTTP request in CI stays on localhost; synthetic FB links are never opened.
CI results, APK and integrity hashes are maintained in PR45.

## One Samsung trial after CI PASS

1. Install 0.5.0 ARM64 as an UPDATE. Never uninstall/reset. Stop on signature mismatch.
2. Open the existing approved group in the POC and wait for the page/extension.
3. Tools > Próba komputerowa • podgląd > new explicit consent. No share-link input.
4. Keep foreground and screen ON for at most 60 s. Allow the one reload and up to
   5 bounded automatic scrolls. STOP at login/CAPTCHA/checkpoint; no retry/bypass.
5. Compare the local selected fields with visible Facebook posts. Copy the count-only
   report via Kopiuj raport (bez ID). The live table can be reopened only while still
   in the foreground/context; only counts remain after pause.

CONDITIONAL_GO: exact identities AND usable sale-candidate fields exist locally;
operator must verify their association/value on the real page. This is not production
GO, proof of completeness, image-content verification or automatic LIVE readiness.
NO_GO: the approved trial yields no usable rows or a required guard cannot be met.
This is a decision for this architecture on this device/group under current limits,
not evidence of an empty group. Do not issue more counter-only APKs as a substitute
for a functional result. Screen-off operation is not asserted; pause must stop.

No merge, production deployment, backend/Supabase/Finder/OLX/Radar changes or paid service.
