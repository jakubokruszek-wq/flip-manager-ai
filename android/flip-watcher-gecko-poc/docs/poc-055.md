# Gecko POC 0.5.5 — bounded thirty-second scrolling

The existing newly consented computer preview now scrolls for up to 30 seconds,
at most 30 attempts spaced by 1000 ms. Each step rechecks the approved document,
nonce and background context, reads scoped DOM and rediscovers the actual feed.
Missing extent is retried within that window; movement is measured after rendering.
No click, verification bypass or extra Facebook request is synthesized.

The original 60-second arm/load/read deadline remains shared. Slow loading shortens
the scroll window: 1500 ms is reserved for final extraction/delivery. The existing
20-ID projection cap remains, and reaching it locally can stop early. Reaching a
feed end does not invent successful movement. Five archive diagnostics are unchanged.

Only the dedicated desktop transport admits up to 64 bodies (previously 16),
retaining 2 MiB per body / 4 MiB aggregate / 8 concurrent streams. Legacy modes
remain at eight bodies and their previous limits. Original bytes still go to the
page unchanged. Exhausted budgets are reported; this is not a completeness claim.
The fresh native consent displays the new duration/step/body limits.

Oferty and its deliberate external links remain unchanged. Pause/screen off,
login/CAPTCHA/checkpoint, navigation or port loss abort and clear RAM. No production
scan, collector/upload, persistent post fields, new services or permission changes.

Validation: Node fake-clock duration/late scroll extent/short remaining deadline/
mid-window context loss, 64-body boundary and retained de-duplication; JVM strict
30-step/movement bounds; real local Gecko first acceptance now requires >=30 s
elapsed with a 45 s shared test budget, then a short 15 s root trial and checkpoint
abort. Existing UI/privacy and full Android16 suites must pass CI. Physical Samsung
30-second behavior and completeness still require the operator test.
