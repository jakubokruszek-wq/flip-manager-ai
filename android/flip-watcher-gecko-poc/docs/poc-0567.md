# 0.5.67 — Watcher group selection and paired source synchronization

The reviewed snapshot contains the eleven enabled GROUP sources in the Watcher registry as of 2026-10-30. Profiles and disabled groups are excluded. The numeric source 402796264871862 and the separate slug lodzsprzedazzakupwynajem remain independent identities.

Tools contains Wybierz grupę Watchera and Połącz / synchronizuj Watchera. Switching closes document operations, invalidates archive callbacks, and loads that group's private encrypted archive. Disk jobs capture the group before queueing. The existing saved-search-v1.bin and its encryption format remain compatible. Other groups use distinct filenames. Delete removes the selected group's results, not the other groups or device token.

Manager's collector setup page creates a device pairing JSON through the existing challenge/cookie pairing flow. The Android client accepts only the exact production Manager origin and valid UUID/token fields. The token is encrypted with a separate Android Keystore AES-GCM key in noBackupFilesDir. It is never sent to a Facebook document or WebExtension, never logged, and excluded from screenshots in the pairing dialog. No Supabase service credential is included.

The only new native requests are GET /api/collector/devices/current and GET /api/collector/facebook/groups at the fixed Manager origin. Redirects are disabled; responses are bounded and subject to timeouts. The feed uses the existing revocable collector device authentication and the Watcher's existing registry. A failed feed does not replace cached configuration. Disabled sources stop being eligible for automation without deleting their history. This release fails closed on sources outside the reviewed eleven; a later expansion needs an explicit protocol/manifest update.

This is **group configuration integration, not offer upload**. Offers, JPEGs, source text and OCR never leave the phone. LIVE_UPLOAD_ENABLED stays false. Do not attach DesktopRow to the old batch import: it lacks authoritative source text/author/publication evidence. The old normalized collector import can overwrite fields and reject projections lacking source intent. Full offer transfer needs a separately reviewed source-data/provenance contract and retry-safe image import, rather than fabricated source content.

Backend changes are isolated in PR 48; the POC remains in draft PR 45. No database schema, active source configuration, scheduler claim, heartbeat or production offer has been changed by this work. Production activation and APK publication require the backend route to be deployed first. Do not ship an APK pointing at a missing route.
