# Gecko POC 0.5.45 — cached OCR followed by manual-review enrichment

Physical 0.5.44 showed OCR DONE (seven cached images, four text results) while fourteen manual-review posts remained. The OCR entry point previously chose cache-only whenever any crop existed. This prevented the consented detail-opening stage from being attempted.

When manual-review rows exist, the single “OCR + uzupełnij brakujące dane” action now requests fresh consent for both stages before starting. Stage 1 runs local OCR on already identity-bound RAM crops. Stage 2 unconditionally invokes the existing exact-link detail runner for the manual queue after successful cached OCR, even if cache OCR produced suggestions. Opening still occurs when the shared OCR image budget has been exhausted, allowing DOM data to be checked. New detail images use only the remaining part of the existing total twenty-image budget. Both stages share one outer three-minute deadline. No intermediate success dialog or second authorization prompt; no automatic reuse of old consent. With no manual queue, cache-only OCR remains valid.

The foreground banner identifies stage 1/2 and 2/2. A successful combined report includes detail-opening counters. A NO_OWN_POST refusal after completed cached OCR is PARTIAL rather than DONE; its actual reason/opened/bound counters are included. The whole attempt may cover more posts than the smaller detail queue; summary validation accounts for that without accepting an oversized opening scope. Legacy count histories remain readable.

Completed cached suggestions may be restored only after NO_OWN_POST if the original exact session/list/group/lifecycle gate remains valid. Unverified or incomplete detail rows are never published on failure. Other failures, engine loss, navigation, pause, cancellation and deadline still erase RAM details. No images, OCR text or IDs are persisted/uploaded. OCR fields remain separate and heuristic.

The known Facebook detail binding refusal is NOT claimed fixed by orchestration: the reader may still stop after two unbound pages. This release ensures those pages are actually attempted after cached OCR and reports the distinction honestly. Manual per-post opening from 0.5.44 remains available.

Validation: 509 Node tests; added JVM summary tests for partial smaller opening queues, successful opening counts, legacy history and invalid combinations. App/instrumented compilation, JVM, isolation and signed APK in CI. Long emulator execution skipped per user request. No real Facebook test by the agent.
