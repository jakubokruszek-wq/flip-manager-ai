## Actual target, not another hit-test guess

A fresh consent dialog defaults to an operator-guided variant. After a fresh
approved-group document is confirmed, the app explicitly displays WAITING. The
operator has up to15s (inside the original60s deadline) to swipe upward in group
content. Passive isolated-content listeners require browser-trusted single-touch
movement, an actual positive scroll delta and a matching scroll event from an
ancestor of that touched element. Scroll events alone are insufficient: scripted
scroll events can be trusted by the browser even without user input. Scripted
TouchEvents are refused. Frames, forms, comments, menus, sidebars, foreign or
detached nodes and active modals are refused. Momentum observation is limited to
one second after a proven swipe ends/cancels; at most64 ancestors plus the root.

Only the observed node is retained, in RAM within that one trial. App sends no
touch input, clicks, native wheel events or media requests in this mode. It then
uses ordinary DOM scrollBy on that node for up to30s/30 automatic commands,
measuring actual movement. It never falls back to a guessed candidate if the
operator does not select a target or the target becomes invalid. At a finite
end it waits for that same target to acquire range. Context changes/pause/port
loss cancel and remove all listeners and references. Gesture coordinates are
transient RAM only, never included in reports, native messages or storage.

This requires ONE real operator gesture at startup; unattended auto-discovery
remains unproven. Existing0.5.16 baseline is available by unchecking gesture mode;
existing extended photo/native path is separately optional and disabled while
gesture mode is selected. Every trial requires fresh consent, options reset.
No extra toolbar buttons. WAITING/ANCHORED hints use only fixed stage/nonce on
the existing private port, strict schema and current-port/nonce checks.
