# Gecko POC 0.5.6 — scroll extent and lazy-feed correction

A reported Samsung run made a few moves and then stopped visibly. Without its
aggregate report, the precise device cause is unconfirmed. Code inspection found
that selection ranked the root first on equal article counts and checked total
extent, but not remaining extent. An exhausted root could repeatedly win over an
inner feed. The prior local loop mock also allowed movement beyond the real bottom.

Selection now excludes targets with <=2 px remaining downward range and prefers
an equally bound inner feed over the root. It continues bounded rediscovery while
waiting for asynchronously added range. No synthetic click, verification bypass,
request replay, repeated up/down gesture or unbounded traversal is introduced.
Retaining 20 IDs no longer silently ends the 30-second window; the model still
retains only 20 unique rows and keeps its existing conflict/deduplication checks.
Shared 60-second deadline and 30 attempts / up to 30 s remain unchanged.

New aggregate-only fields: scrollElapsedMs (0..30000), scrollStalls (bounded by
attempts minus successful moves), scrollAtEnd (maximum exhausted candidate count,
not posts) and scrollNoTarget (0..30 one-second waits). Old 22- and 30-field reports
remain readable, zero-padding new counters only in the parsed copy. No raw data or
ID persistence changes. Fresh protocol requires the complete reviewed schema.

Node tests now clamp scroll position to actual extent, cover exhausted root versus
inner feed, competing containers, finite bottom, delayed growth after 10 seconds,
20 retained IDs with a full window, blocked commands and mid-window context loss.
Real local Gecko fixture starts with only 1800 px spacer and appends 20000 px only
1800 ms after an actual bottom scroll event. Acceptance requires reaching that
initial end, waiting for growth, >=15 attempts and >=29 s measured scroll time.
It also covers the shorter root trial and checkpoint interruption. This exercises
a real lazy-load boundary; it does not prove Facebook will supply more content.

Install 0.5.6 ARM64 as update, without uninstall/reset. Run the existing newly
consented computer preview on foreground Samsung with screen on. Check Oferty and
aggregate elapsed/moves/waits/end-range counts. Preserve 64 response / 4 MiB total
limits, original signing/profile, no scan/upload/production changes. Completion
and locked-screen behavior remain unverified on the physical phone.
