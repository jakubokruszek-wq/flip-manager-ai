# Gecko POC 0.5.12 — measured-feed recovery and explicit viewport readiness

The physical Samsung 0.5.11 still reports four DOM moves, 24 no-target waits,
zero accepted wheel operations, and zero crop proposals. Those aggregate values
cannot distinguish no hit point, rejected native requests, missing ACK, missing
module/consent, or missing native window focus. Do not assert a unique physical
cause or claim the Samsung problem fixed from an emulator result.

## Changes

Before the bounded viewport work, a fresh private metadata-only probe checks the
actual native gate, visible native view, and Android window focus. Codes: 0 ready,
1 gate, 2 view/geometry unavailable, 3 window focus absent, 4 no matching ACK.
At most three short probes, all inside the same original trial/scroll deadline;
no input, image read, upload, persistence of personal data, or new consent is
performed by a probe. Existing default-off consent remains mandatory. Readiness
never overrides the actual gate for a later action.

The report now separates module/grant/readiness, probe code, actual wheel
requests, explicit rejections, ACK timeouts, missing hit points, and number of
network posts carrying exact attachment evidence. These are fixed bounded
numeric counters only. Histories with 45 and earlier counter sets remain
readable without rewriting or deleting them. Zero attachment evidence must not
be presented as a gallery of zero photos.

Within one trial, remember the container only AFTER an ordinary DOM command
has demonstrably moved it. If subsequent normal selection has no remaining
range and the current identity-based hit helper rejects its cards, official
GeckoView input can return to a visible article inside that same moved feed.
It must still be connected to the same document, contain a current top-level
article, and pass visible hit checks and all context checks. Never target
iframes, controls, dialogs, comments, navigation or sidebars. No DOM styles,
security challenges, navigation guards, source IDs or post IDs are changed.
A cross-post link is not proof of an own-group post: this path permits only
ordinary scrolling; it does not widen extraction or photo association.

The native dispatch ACK remains distinct from measured actual movement.
Native refusals/timeouts are limited to three failures. Existing 30 s/30 steps,
shared 60 s, 20 post IDs, 3 visible RAM crops/post and response limits remain.
No new touch/click injection, extra media download, collector or production use.

## Acceptance

Node tests distinguish no point, denial, timeout and focus failure; verify the
recently moved target is not stale, foreign-document or unrelated. JVM verifies
strict probe metadata, telemetry bounds and old 45-counter history.

Actual GeckoView tests retain every earlier strict pixel/movement assertion.
An additional local fixture removes semantic feed markup and supplies cross-post
cards: normal scrolling must first move the feed, then actual wheel must unlock
a NEW exact own-group offer. Cross-posts must not enter own-group rows or crops.
Another actual Android test displays a modal dialog, requires probe code3, then
dismisses it and requires readiness without any input or screenshot action.

No agent-side Facebook test/login. Physical Samsung and screen-off behavior
remain unconfirmed. APK and authoritative CI results are linked from Draft PR45.
