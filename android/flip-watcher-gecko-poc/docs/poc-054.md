# Gecko POC 0.5.4 — separate Offers tab with deliberate active links

## User flow

The browser content has Facebook / Oferty tabs. The default is Facebook; browser
height must still meet the existing 70% viewport acceptance test. A successful
preview automatically selects Oferty. It shows only eligible candidates, individual
cards with Polish price/area/rooms, location, recognized-photo count and exact ID.
The canonical URL is clickable and Otwórz post is an accessible explicit button.
The technical report and rejected-post reasons remain under a separate action;
copy still includes only aggregate report data. Archive tools remain collapsed.

Switching tabs stays in the same Activity/session/document and retains RAM details.
No navigation, login, scan, collector, upload or link open occurs from switching or
rendering. Measurement controls return to Facebook before work; tabs are disabled
during active work. Opening/reloading the group restores the Facebook view.

## Link boundary

Only deliberate click on a current eligible card may open its exact canonical
HTTPS www.facebook.com/groups/<approved-slug>/posts/<numeric-id>/ URL. URL policy
rejects credentials, query/fragment, foreign group/host, mismatched/media/fake IDs,
other schemes and non-candidates. The Activity checks current row identity and
foreground state again; stale callbacks cannot open a previous result.

ACTION_VIEW + CATEGORY_BROWSABLE carries only that URL, no extras, text, fields,
credentials, cookies, author, backend payload or referrer. Android's Facebook app
or browser handles it, OUTSIDE the bounded POC session. This avoids silently
expanding the approved-group-root navigation/collector permission. The existing
POC session remains at its group and no scan consent is reused.

The panel explains that leaving the app clears the list. Before dispatch, all
current details, view text/tags/listeners (including held detached views), report
copies and row references owned by the UI are cleared. Pause/context/port loss and
session close also clear. If no external handler can open the URL, a fixed local
message is shown; data are not restored. This intentionally means opening one
external link does not preserve other cards. No persistence relaxation was inferred
from the request for a tab. Fresh new preview consent is required after clearing.

## Validation

Pure JVM link-policy tests cover valid eligible exact URL, scheme/host/group/
credentials/query/fragment/ID mismatch and non-candidate exclusions. Android16
focused acceptance includes cards-only separation, tab retention, aggregate-only
clipboard/history, clearing both cards/report after pause/recreate and old scan/
link-history preservation. An Instrumentation ActivityMonitor intercepts ACTION_VIEW
before external launch, so clicking is tested without contacting Facebook. It checks
exact URL/no extras and that stale buttons are inert after clearing/pause.
A real local Gecko session in the actual PocActivity is toggled between tabs;
its document URL, port generation and connection must remain unchanged. Existing
real-Gecko extraction/scrolling/verification and full regressions still run.

APK/results/integrity links in Draft PR45. Same package and existing test signature;
update only, never uninstall/reset. No main/production/PR44 changes, deployment,
merge, response-limit changes, background collection, raw-post persistence or upload.
Screen ON / foreground acceptance only; no locked-screen claim.
