# POC 0.5.19: wait for a loaded page and an input-ready window

Samsung 0.5.18: the operator reports that the visibly washed-out Facebook page
cannot be swiped, including after attempting to close its small Close control.
The earlier attribution to a page overlay was a hypothesis, not a confirmed cause.
No physical root cause or successful Samsung scrolling is claimed here.

A concrete startup race was found: a new document_idle extension port could
trigger the 15-second WAITING hint before Gecko onPageStop(success) or native
window focus. DesktopSessionPreview now requires an explicit pageReady callback;
PocActivity resets its completion flag and progress on every page start and
requires successful page completion plus 100 percent progress. A supplied
GeckoView must be attached, shown, enabled, own window focus, and regain view
focus before the content command is sent. These waits use the original 60-second
deadline; PAGE and FOCUS timeouts are distinct persisted reasons. Native dialogs
are not dismissed by the readiness code. Page overlays, CSS and input handlers
are not removed or overridden.

During a desktop trial, the existing session button becomes Przerwij probe.
It cancels the trial and temporary preview without closing the browser session,
so the operator can return to manual interaction immediately. Outside a trial,
its existing open/close-session behavior is unchanged. No consent is reused.

The previous Android gesture fixture called GeckoView.onTouchEvent directly.
A new regression uses Instrumentation.sendPointerSync through the real Android
window for both accepting the actual consent dialog and swiping the local page.
A native control row sits above the browser. The test holds page readiness and
then deliberately holds focus in another native dialog: WAITING must not appear
in either state. Only after releasing both gates may real touch select the long
pane and the automatic continuation perform at least 25 movements and extract
the newly loaded exact fixture offer. All input helpers remain androidTest only.
Two JVM regressions cover the shared deadline and cancellation during PAGE/FOCUS.

Validation is recorded in PR45 and Actions for the final commit. Node: 52 core
and 317 adapter tests, zero failures/skips. JVM/emulator results are not assumed
from earlier versions. Images/native wheel remain off in the default gesture
mode. No production services, database, old offline history, outbox, one-shot
limit or signing identity are changed. No real Facebook scan or login is run.

Operator validation: update without uninstalling; open the approved group, start
one freshly consented local desktop trial, wait for TERAZ, then swipe once. Use
Przerwij probe if manual input remains blocked; do not infer successful scrolling
from a conditional offer verdict alone. Report gestureTouches, gestureAnchored,
gestureScrollMoves/Steps and whether manual input works after cancellation.
A physical test is still required; screen-off operation is unconfirmed.
