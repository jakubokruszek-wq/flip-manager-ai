# Gecko POC 0.5.18 — reachable consent actions on compact screens

Physical0.5.17 screenshot shows the consent message consuming the screen;
positive/negative actions and custom options are unreachable. Mixing a very long
AlertDialog message with a custom options view was unusable on the Samsung.

Replaced it with one fixed-size native dialog: short title, weighted scrollable
body and an independent full-width vertical footer. Accept/cancel remain outside
the ScrollView, with48dp minimum touch targets. Height/width fit the activity's
visible window, accounting for system bars; no title/message can expand past the
fixed window. Text uses normal sp scaling, not forced small font.

The summary clearly states fresh one-group reading of posts/network responses,
20-post/60s limits, one-gesture then30s behavior, local transient preview and stop
conditions. Complete original privacy/scope/budgets remain in an expandable body
section. That section scrolls with options, never with the footer. Gesture starts
selected; experimental photos/native remain off and disabled until gesture is
unchecked. Each opening resets choices. Accept snapshots flags, dismisses the
dialog then runs the unchanged activity/context/consent guards; cancel/back do
not start a trial. Repeated acceptance is guarded.

No changes to gesture recognition, DOM scrolling, extraction, source IDs,
filters, transport, native photo handling, outbox/history or production.
Version/signature-compatible update, no uninstall/reset.

New Android16 tests use the actual dialog at320dp×360dp and fontScale2.0. Both
buttons must be fully inside the dialog AND usable screen. A real Android input
tap must accept once with correct safe defaults. After expanding and scrolling
long details, footer coordinates must remain identical; a real cancel tap must
not grant consent, and a newly created dialog must have safe defaults again.
Screenshots are captured from the local native dialog (no Facebook/account) and
uploaded with instrumented reports. Focused consent tests run before the longer
existing GeckoView suite; full tests remain required. Results and APK are in PR45.

Samsung after UI correction and actual Facebook automatic continuation still
require operator verification. One operator gesture remains required in default
mode; screen-off and collector pilot are unconfirmed/inactive. No merge/deploy.
